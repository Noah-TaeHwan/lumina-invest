# Lumina Invest 프로젝트 개요

이 프로젝트를 처음 보는 사람이 "무엇을, 왜, 어떻게 만들고 있고, 지금 어디까지 왔는가"를 한 번에 파악하도록 정리한 문서입니다. 세부 수치와 결정 근거는 맨 아래 링크한 원문 문서에 있습니다.

기준일: 2026-10-06. 이 문서는 AI(Claude Code)가 저장소의 README·설계 문서·실험 리포트를 바탕으로 작성했습니다.

## 1. 한 줄 요약

**분석글을 붙여 넣으면 문장마다 DART 공시와 대조해 ✅·⚠️·❔로 표시하는 "발행 전 공시 팩트체커"**를 만들고 있습니다. 판정에는 외부 문장 판정 모델과 코드 규칙을 함께 쓰고, 성능은 사전등록한 실험으로 공개합니다.

| 구분 | 내용 |
|---|---|
| 출발점 | 공개 원본 코드 [edumgt/lumina-invest](https://github.com/edumgt/lumina-invest)(FastAPI, 메뉴 50여 개)를 부품 상자로 삼아 개인 저장소에서 조립 |
| 핵심 | 외부 문장 판정 모델(선택지 중 하나를 확률과 함께 고르는 판단 모델)을 금융 리서치에 쓸모 있게 붙이는 것 |
| 목적 | 투자 리서치 직무(애널리스트)와 AI 제품 역량을 함께 보여 주는 포트폴리오 |
| 현재 단계 | 팩트체커 설계 확정, 1주차 구현 진행 중(아직 동작 확인 전) |

이 프로젝트는 투자 권유가 아닙니다.

## 2. 왜 만드는가 — 문제와 대상

**문제.** 한국 상장사 분석글을 자기 이름으로 발행하는 사람은 글 속 숫자·회사·기간이 공시와 맞는지 발행 전에 직접 확인해야 합니다. 지금은 DART 뷰어에서 Ctrl+F, 엑셀에 숫자를 옮겨 대조하거나, 아예 검수를 건너뜁니다. AI로 초안을 쓰면 그럴듯하지만 틀린 문장이 섞여 이 검수가 더 무거워집니다.

**대상.** 금융 관련 글을 쓰는 사람. MVP의 첫 사용자는 **Substack·블로그·텔레그램에 한국 기업 분석을 정기 발행하는 개인**으로 좁혔습니다. 기관 애널리스트는 사내 검수 절차·보안 제약 때문에 증거를 만든 뒤 넓힙니다.

**수요 증거(솔직하게).** 지금 있는 증거는 설립자 본인의 행동뿐입니다. 노아는 무신사 분석 때 DART·XBRL 원자료를 직접 파싱해 매출을 원 단위까지 교차검증한 뒤 발행했습니다. 다른 사람의 행동 증거는 아직 없고, 이것이 가장 큰 위험입니다(발행자 5명 인터뷰가 다음 과제).

**위치.** 사용자는 쓰던 AI 도구(ChatGPT 등)를 그대로 씁니다. 우리는 글을 대신 쓰는 생성기가 아니라 **검수 레이어**입니다.

**경쟁.** 가장 가까운 국내 제품은 DartPoint AI(사이냅소프트, 무료, 문서·페이지 단위 근거 연결)입니다. 해외 제품(Terminal X, AlphaSense, Fiscal.ai)은 질문에 답하며 인용을 붙이는 방식입니다. "붙여 넣은 한국어 글을 문장 단위로 DART와 대조"하는 국내 서비스는 조사 범위에서 찾지 못했습니다(없다는 증명은 아님). 자세한 내용은 [경쟁 조사](research/2026-10-06-ai-investment-research-competitors.md)에 있습니다.

## 3. 사용자 시나리오

```
① 랜딩(로그인 없음)
   "분석글을 붙여 넣으면 문장마다 DART 공시와 대조합니다.
    ✅는 공시와 일치한다는 뜻이지, 사실 보증·발행 승인이 아닙니다."
        │
② 회사 선택 ── 데모 범위: 삼성전자 · SK하이닉스 (최근 3년 공시)
        │
③ 출처 선택(내 초안 / AI 답변 / 남의 글) + 붙여넣기 (익명: 2,000자 · 30문장)
        │
④ 결과 화면 ── 문장별로 판정이 끝나는 대로 채워짐
   ├ 상단 요약: ✅ n · ⚠️ n · ❔ n · 건너뜀 n
   ├ ⚠️·❔ 문장 먼저, 펼치면 근거 공시 문단 · 보고서명 · 기간 · 접수번호
   ├ 숫자가 어긋나면 공시 숫자(XBRL 값)를 나란히 표시
   └ 검수하지 않은 문장은 접어서 이유와 함께 표시 + [직접 검수 요청] 버튼
        │
⑤ 작성자가 표시를 보고 직접 확인·수정 → 발행 판단은 사람이
```

1주차 공개판은 익명(로그인 없음)만 엽니다. 로그인·결과 저장·검수 결과 공유 링크(작성자가 글에 붙이면 독자가 문장별 근거를 봄)는 2주차에 붙일지 정합니다.

## 4. 동작 원리

### 처리 3단계

```
초안 텍스트
   │  문장 분리 (코드)
   ▼
[1단계] 검수 대상 분류
   ├ 숫자·회사명·기간이 든 문장 → 무조건 검수 (규칙)
   ├ 의견·전망·목표주가 → 검수 안 함 (회색, 이유 표시)
   └ 다른 회사가 주어 / 공시 범위 밖 기간 → 범위 밖 (회색)
   │
   ▼
[2단계] 공시 대조
   ├ 문장의 기간(연도·분기·'작년' 같은 상대 표현)을 해석해 볼 문서를 좁힘
   │  (상대 표현은 실행일이 아니라 기준 시점 = 적재된 최신 보고서 기간 기준)
   ├ 재무 계정 숫자(매출·영업이익 등) → XBRL 수치와 코드로 직접 비교
   ├ 공시 문단 검색(벡터 검색, 8개) → 숫자 일치 확인(코드)
   └ 판정 모델 판정: 이 문단들이 문장을 지지 / 반박 / 근거 없음?
   │
   ▼
[3단계] 결과 표시 — LLM 없이 코드로
   판정·근거 문단·XBRL 값을 그대로 보여 줌 (요약하면서 새 오류가 섞이지 않게)
```

**왜 이렇게 나눴나**

- **숫자는 코드, 의미는 판정 모델.** 숫자 대조는 모델보다 코드가 정확합니다(단위 환산 조·억·백만, 반올림 일치 포함). 판정 모델은 "이 문단이 이 문장을 뒷받침하는가" 같은 의미 판단에 씁니다.
- **놓침 방지가 우선.** 1단계에서 숫자·회사·기간 문장은 규칙으로 무조건 검수합니다. 처음에는 판정 모델이 1단계 분류를 맡는 안(노아 제안)도 검토했지만, 제품에서는 규칙 분류로 시작하고 도그푸드에서 "규칙만" 대비 이길 때 판정 모델 분류를 켭니다.
- **3단계에 LLM 없음.** 판정 결과를 LLM이 다시 요약하면 확인되지 않은 표현이 새로 섞일 수 있습니다. GPU 없이 배포할 수 있는 이유이기도 합니다.

### 판정 배지

| 배지 | 뜻 |
|---|---|
| ✅ | 문장 **전체**가 공시로 지지됨 |
| ⚠️ | 공시와 어긋날 수 있음(숫자 하나라도 XBRL과 다르면 여기) — 직접 확인 필요. ⚠️의 정확도는 아직 따로 검증하지 않았습니다(도그푸드에서 측정) |
| ❔ | 검색 범위 안에서 못 찾음. 숫자만 XBRL과 맞고 나머지가 확인 안 되면 "부분 확인"으로 표시 |
| ⊘ | 판정 불가(오류·혼잡·한도) |
| 회색 | 검수 안 함(의견·범위 밖·다른 회사) — 이유와 함께 접어서 표시 |

숫자 하나가 맞았다고 문장 전체를 ✅로 올리지 않습니다. "부분 확인"을 따로 두는 이유입니다.

### 기간을 다루는 법

공시에는 기간이 세 겹입니다: 문장이 말하는 기간, 보고서가 다루는 기간, 공시를 낸 날. 이 셋을 나눠 저장하고, 같은 기간 값이 여럿이면 **정정 > 원본, 확정(정기보고서) > 잠정실적** 순으로 씁니다. 실제로 삼성전자 2026년 2분기 잠정실적에 정정 공시가 있습니다(매출 171.00조 → 171.50조 원).

## 5. 구조와 기술

### 팩트체커 경로(새로 만드는 부분)

```
public/factcheck.html ──POST /api/factcheck──▶ app/factcheck_main.py (별도 진입점)
        ▲                                         │ 익명 한도(원자적 예약, PostgreSQL)
        └──GET /api/factcheck/{job_id} 폴링───────┤ 결과는 메모리에만 15분(원문 영구 저장 안 함)
                                                  ▼
                                    app/services/factcheck/
                                    ├ collect·store  공시 수집·문서 단위 저장(Qdrant)
                                    ├ xbrl           XBRL 재무 수치 적재·대조
                                    ├ triage·scope   1단계 분류·기간 해석·다른 회사 판별
                                    └ pipeline       단계 연결 → 문장별 결과 스트림
                                                  │ import로만 재사용
                                    app/services/evidence/  (기존 근거 판정 엔진, 수정 금지)
```

- **원본 앱과 분리.** 원본 `app.html`(메뉴 50여 개)과 원본 라우터를 고치지 않고, 팩트체커 전용 페이지와 진입점을 따로 둡니다. 배포판은 Redis·Neo4j 없이 PostgreSQL·Qdrant만 씁니다.
- **기존 엔진은 읽기 전용.** `app/services/evidence/`는 사전등록 실험의 코드 해시 대상이라 고치지 않고 import로만 재사용합니다.
- **비용 상한.** 판정 모델은 유료 외부 API라, 호출 전에 PostgreSQL에서 토큰을 원자적으로 예약하고 상한을 넘으면 호출하지 않습니다. 동시에 많이 써도 하루 상한을 넘지 않게 하기 위해서입니다. 공개 서버의 상한 값은 공개 전에 노아가 정합니다(미정).
- **개인정보.** 익명 초안 원문은 DB·로그에 남기지 않습니다. 판정을 위해 문장과 공시 문단이 외부 API로 전송된다는 사실을 입력 전에 고지합니다.

### 데이터

| 데이터 | 출처 | 용도 |
|---|---|---|
| 정기보고서(사업·반기·분기) I·II·III절(1주차) | OpenDART `document.xml` | 문단 검색·판정 모델 판정 |
| 잠정실적(공정공시, 정정 포함) | OpenDART | 최신 분기 숫자·증감률 대조 |
| XBRL 재무 수치(연결·별도) | OpenDART `fnlttSinglAcntAll` | 재무 숫자 코드 대조 |
| 상장사명 사전 | OpenDART 고유번호 목록 | "다른 회사가 주어" 판별 |

수집은 로컬에서 하고(키가 로컬에만 있음), 서버에는 Qdrant 스냅샷과 JSON을 올립니다. 갱신은 분기 1회 수동입니다.

### 이미 만든 기능(로컬 동작 확인, 배포판에서는 숨김)

| 기능 | 하는 일 |
|---|---|
| 공시 근거 모드 | AI 채팅 답변 문장마다 ✅·⚠️·❔와 근거 공시 문단(로컬 8B 모델 + 판정 모델) |
| 판단 일지 | 판정 한 건에서 내 판단·확신·메모를 기록하고, 다시 볼 날에 공시가 바뀌었는지 비교 |

## 6. 신뢰 장치 — 사전등록 실험

이 포트폴리오의 실험 주장은 **미리 기준을 등록하고, 평가 세트는 한 번만 열고, 실패도 공개하는** 방식으로 냈습니다. 사전등록 파일·실행 원장은 결과에 맞춰 고치지 않습니다.

| 실험 | 질문 | 결과 |
|---|---|---|
| Gate Lab | 비트코인 5분봉 돌파 신호의 실패를 판정 모델이 가려내는가 | **판정력 없음**(홀드아웃 AUC 0.513, 같은 특징의 로지스틱 회귀 0.649) |
| 근거 판정 Stage 1 | AI 답변 문장이 공시 문단으로 지지되는지 판정하는가 | **판정력 있음**, 최고 기준선(어휘 겹침)과 실용적 동등(AUC 0.979 대 0.984). NLI·로컬 LLM·임베딩보다 크게 높음. 1B 생성기가 문단을 거의 그대로 옮겨 써서 어휘 겹침이 강했던 조건이며, AUC는 순위 능력이지 ✅ 정확도 보증이 아님 |
| A-2 채팅 연결 | 8B 모델 답변에서도 쓸 만한가 | ✅ 정밀도 0.903이지만 ✅ 예측이 144건으로 사전등록 하한(150건)에 못 미쳐 **정밀도 관문은 미확인**(기술 통계로만 보고). 주어만 바꾼 문장 정확도 0.57로 약점 확인 |
| A-3 주체 확인(코드) | 주어 바꿔치기를 코드로 막는가 | 0.642 → 0.848로 개선됐지만 기준(0.90) 미달 → **실패**, 기본 정책 유지 |
| A-4 주체 질문(판정 모델, 탐색) | 판정 모델에 주체 질문을 더하면 나아지는가 | 사전등록 전 탐색 단계에서 진행 기준 미달 → 확인 세트 전에 중단 |

가격 실험의 정답은 코드가 계산한 손실 여부입니다. 공시 근거 판정 실험(Stage 1·A-2~A-4)의 정답은 AI 두 모델(Claude·Codex)이 독립적으로 만들고 조정한 **AI 참조 라벨**이며 사람 감사는 하지 않았습니다.

**팩트체커의 성능 검증(계획): 증권사 리포트 변조 도그푸드.** 삼성전자·SK하이닉스 증권사 리포트를 넣고, 확인 가능한 문장의 숫자·단위·기간·증감 방향·주어를 일부러 바꿔 잡아내는지 봅니다. ① 변조 탐지율과 ② 맞는 문장을 틀렸다고 하는 오경보율을 반드시 함께 잽니다(한쪽만 재면 "전부 ⚠️"인 도구가 만점이 됨). 리포트 원문은 저작권 때문에 로컬에만 두고, 공개는 집계 수치와 짧은 사례만 합니다.

## 7. 개발 방식

| 역할 | 담당 | 하는 일 |
|---|---|---|
| 방향·승인 | 노아 | 제품 방향, 외부 공개·AWS 비용 같은 승인 사항 |
| 리드·검수 | AI 리드(로컬 Claude Code) | 설계 결정, 작업 발주, PR 검수·병합, 실데이터 실행 |
| 구현 | Claude Code 클라우드 세션 | 작업 단위로 병렬 구현, 테스트 먼저 작성, PR까지 |
| 교차 검수 | Claude 리뷰 서브에이전트 + Codex(다른 계열 모델) | 같은 계열 모델의 맹점을 피하려고 둘 다 사용 |

- **로컬과 클라우드 분담.** DART 수집·판정 모델 실호출·Ollama·평가 재실행은 키와 데이터가 있는 로컬에서만 합니다. 클라우드 세션은 코드·문서·단위 테스트까지만 합니다(테스트는 저장소에 커밋한 공개 공시 고정 자료로).
- **PR마다 검수.** 로컬에서 전체 테스트(빈 PostgreSQL 포함)와 e2e 5종을 2회 돌리고, Claude 리뷰와 Codex 교차 검수를 받은 뒤 병합합니다.
- **규칙.** main 직접 커밋 금지(브랜치→PR), 테스트 먼저(RED→GREEN), 키·`.env` 커밋 금지, 공개 문서에 공급자 이름·가격 미기재, AI가 만든 라벨·문서는 AI 작성이라고 표시.
- **기획 도구.** gstack office-hours(스타트업 관점 진단)로 방향을 정하고 plan-eng-review로 구현 계획을 고정했습니다. 결정은 근거와 "이 결정을 뒤집는 증거"를 함께 적습니다.

## 8. 현재 상태와 로드맵

**완료**
- 기존 앱 로컬 실행 환경, 근거 판정 엔진, 공시 근거 모드, 판단 일지, 관심종목·지표 출처(로컬 실스택 확인)
- 사전등록 평가 4건과 A-4 탐색(위 표), 경쟁 조사
- 팩트체커 설계·엔지니어링 검토·Codex 외부 검토(11건 반영), 실제 공시 구조 확인(T0)

**진행 중 — 1주차**

| 작업 | 내용 | 상태 |
|---|---|---|
| T1 | 공시 수집·문서 단위 저장·XBRL·회사명 사전 | 클라우드 구현 중 |
| T2 | 분류·기간 해석·XBRL 대조·판정 연결 | 클라우드 구현 중 |
| T3 | 별도 진입점·익명 API·비용 상한·화면 | 클라우드 구현 중 |
| T4 | 배포 구성·HTTPS·데이터 업로드 절차 | T3 뒤. AWS 생성은 노아 승인 후 |
| T5 | 리포트 변조 도그푸드(사전등록·조정 세트) | T1·T2 뒤 |

**2주차:** 로그인·저장·공유 리포트 링크를 붙일지 결정하고 구현, 사례 정리와 시연 영상.

**그 뒤(범위 밖):** 소형 모델+판정 모델 조합과 대형 모델의 비용·정확도 비교(A-5), 판단 일지 연결, 종목 확대, 수정 제안 기능.

**성공 기준(요약)**
- 노아가 직접 검수한 새 초안의 정답표와 도구 결과를 대조하고 걸린 시간을 비교
- 배포 후 4주 안에 발행자 5명이 자기 초안을 넣고, 2명 이상이 다음 글에서 다시 사용
- 로그인 없이 첫 문장 판정 10초, 20문장 30초 안(목표, 미측정)
- 공개 첫 주 비용 상한 초과 0회, 익명 원문 저장 0건(상한 값은 공개 전 결정)

## 9. 알려진 한계

- **주어 바꿔치기에 약합니다.** 회사·부문·제품 이름만 바꾼 문장이 ✅로 넘어갈 수 있습니다(A-3·A-4 미통과, 공개). 화면에 상시 표시합니다.
- **✅는 발행 승인이 아닙니다.** 검색된 공시 문단과 일치한다는 뜻일 뿐입니다.
- **범위가 좁습니다.** 두 종목, 최근 3년, 정기보고서 I~III절(재무제표 포함)·잠정실적·XBRL 핵심 계정. 설계는 정기보고서 전체 절을 목표로 하지만 1주차는 분량 때문에 III절까지 적재합니다. 그 뒤 절(주석 등), 주요사항보고서, 대부분의 파생 지표는 아직 범위 밖입니다.
- **정답이 AI 라벨입니다.** 사람이 원자료로 확인한 표본 감사는 도그푸드에서 추가할 계획입니다.
- **외부 사용자 증거가 없습니다.** 실사용자 0명, 수요 증거는 설립자 본인뿐입니다.
