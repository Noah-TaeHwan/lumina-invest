# Lumina JEV Gate Lab — 설계

- 작성일: 2026-10-01
- 상태: 설계 승인(대화), spec 검토 대기
- 결정권자: 노아 (설계 방향 승인, 세부 선택은 작성자에게 위임)
- 근거: Codex 기획(2026-10-01), Opus 5.5 xhigh 교차 검수 `APPROVE_WITH_CHANGES`(F1~F8), Vault `typesafe-jev`의 2026-09-26 트레이딩 적합성 기록

## 1. 목적

1분봉 재생 백테스트에서 규칙 전략의 진입 신호에 JEV 게이트를 붙였을 때, 실측 지연과 비용을 반영한 뒤에도 같은 차단율의 대조군보다 나은지 검증한다. 결과가 긍정이든 부정이든 같은 형식으로 공개한다.

포트폴리오가 보여주는 것은 세 가지다.

1. 미래 정보를 쓰지 않는 이벤트 재생과 지연을 반영한 체결 모형
2. 실측한 JEV 지연·실패율·비용
3. 차단율을 맞춘 대조군과 비교한 JEV 게이트 효과 추정치와 신뢰구간

### 가설

| ID | 가설 | 판정 근거 |
|---|---|---|
| H-speed | JEV 왕복 지연은 1분봉 주기 안에서 판단을 끝낼 만큼 짧다 | Stage 0 지연 p50/p95/p99 |
| H-predict | JEV의 "실패할 돌파" 확률은 실제 거래 결과와 관련 있다(집단 수준) | 후보 거래 손실 여부 대비 AUC, Brier 점수 |
| H-profit | 홀드아웃에서 JEV 게이트의 비용 차감 성과가 차단율을 맞춘 대조군보다 낫다 | 대조군 대비 차이의 블록 부트스트랩 신뢰구간 |

귀무가설: JEV 게이트는 같은 차단율의 무작위 차단·결정론 필터·로지스틱 회귀와 차이가 없다.

### 사전 근거와 기대 결과

Vault의 2026-09-26 기록은 "JEV의 속도는 가격 알파용이 아니다"라고 적는다. 이 기록은 2차 출처라 직접 검증하지 않았다. Opus 검수 F1도 숫자 특징만 넣으면 JEV가 코드로 계산할 수 있는 정보를 반복할 가능성이 크다고 지적했다. 그래서 **가장 가능성 높은 결과는 귀무가설 기각 실패**로 본다. 같은 기록에서 JEV가 효과를 낸 곳은 규칙이 못 정하는 자유 서식 텍스트였고, 이것은 Stage 2 가설로 둔다.

## 2. 고정 결정

| 항목 | 결정 |
|---|---|
| 시장 | Binance 현물 `BTCUSDT`, 롱 전용(보유↔현금), 거래당 고정 1,000 USDT, 시장가 |
| 데이터 | `data.binance.vision` 월별 1분봉(`klines/1m`)과 체결(`aggTrades`). 파일마다 `.CHECKSUM`의 SHA-256을 검증하고 다운로드 일시를 원장에 기록 |
| 기간(UTC) | 개발 2025-10-01~2026-04-30 · 검증 2026-05-01~2026-06-30 · 홀드아웃 2026-07-01~2026-09-10 · 공개 이후 구간 2026-09-11~2026-09-30 |
| 기본 규칙 | Donchian 돌파. 진입 후보는 `close[t] > max(high[t-N..t-1])`이고 직전 봉에서는 같은 조건이 거짓인 봉. N ∈ {30, 60, 120}은 개발 구간에서만 고른다 |
| 청산 | 모두 코드가 결정. 봉 마감 기준으로 `close ≤ 진입가 − 2·ATR14`이면 손절, `close ≥ 진입가 + 3·ATR14`이면 익절, 120봉 경과 시 시간청산. ATR은 신호 봉 값으로 고정 |
| JEV 호출 | 모든 진입 후보에서 호출. 포지션 상태는 입력에 넣지 않아서 어느 갈래든 같은 호출 결과로 재생할 수 있다. `jev-1.13.0` 고정, 응답의 `model`을 매번 기록. 홀드아웃·공개 이후 구간 후보는 `prereg_holdout.json` 커밋 뒤에만 호출 |
| JEV 질문 | Noul 1개. yes 확률 = 이 돌파가 실패할 확률(4절) |
| 게이트 | `p_fail ≥ τ`이면 차단. 호출 실패·타임아웃도 차단 |
| 체결 | 결정 시각 = 봉 마감 + 지연. 체결가 = 체결 시각이 결정 시각 이상인 첫 aggTrade 가격. 매수 +1bp, 매도 −1bp 슬리피지. taker 수수료 0.1% 양방향 |
| 오래된 신호 | 지연이 5초를 넘으면 진입하지 않고 `stale`로 기록 |
| 예산 | JEV 하드 상한 $5. 문서 가격 $0.042 / 입력 100만 토큰(출력 무료) 기준 추정치는 1달러 미만 |
| 금지 명칭 | "HFT", "초단기", "알파", "수익 보장" |

시간 단위: 2025-01-01 이후 Binance 현물 아카이브의 타임스탬프는 마이크로초다. 로더는 자릿수로 단위를 판별해 마이크로초 정수로 통일한다. 2025-10-01 1분봉의 첫 행 `open_time=1759276800000000`으로 확인했다.

## 3. 시간 정의와 데이터 흐름

```
1분봉 로드 ─▶ 봉 마감 시각 t_c = open_time + 60s
           ─▶ 특징 계산 (close_time ≤ t_c 인 봉만 사용)
           ─▶ 진입 후보 판정 (규칙)
           ─▶ JEV 호출 (캐시, 지연 L 측정)
           ─▶ 게이트 판정 (갈래별)
           ─▶ 결정 시각 t_d = t_c + L  (L > 5s 이면 stale)
           ─▶ 진입 체결 = t_d 이후 첫 aggTrade
           ─▶ 청산 판정 (진입 체결 이후 마감된 봉에서 코드 규칙)
           ─▶ 청산 체결 = 해당 봉 t_c 이후 첫 aggTrade
           ─▶ 거래 원장
```

- 한 번에 포지션 하나만 보유한다. 보유 중에 나온 후보는 해당 갈래에서 무시한다.
- 손절·익절은 봉 마감 종가로만 판정한다. 봉 안에서의 가격 경로는 쓰지 않으며, 모든 갈래에 같게 적용되는 단순화다.
- 지연 L은 각 후보를 실제로 호출할 때 잰 값이다. 오늘의 네트워크 지연을 과거 시점에 옮긴 근사라고 리포트에 명시한다.
- 체결은 "첫 체결 가격"의 근사다. 호가·대기열·시장 충격은 반영하지 않는다.

### 체결 데이터 처리

aggTrades는 BTCUSDT 기준 압축 상태로 월 약 358MB다. 체결은 요청 방식으로 처리한다.

1. 1분봉만으로 후보, 갈래별 진입 시각을 먼저 계산한다.
2. 해당 월 aggTrades CSV를 청크 단위로 읽어 요청 시각마다 첫 체결 `(time, price)`를 찾는다. 정렬 배열의 `searchsorted`를 쓴다.
3. 진입가로 청산 봉을 정한 뒤 같은 방식으로 청산 체결을 찾는다. 청산이 다음 달로 넘어가면 다음 달 파일에서 이어서 찾는다.
4. 찾은 체결은 `lab/data/fills/`에 캐시한다. 원본 zip은 `lab/data/raw/`에 두고 별도 명령으로만 지운다. 둘 다 Git 추적 대상이 아니다.

Stage 0은 1분봉만 쓰고 aggTrades는 받지 않는다.

## 4. JEV 게이트

요청 형식은 `POST https://api.typesafe.ai/v1/systemone`이고 본문은 `{model, state, questions}`다. 영어가 공식 문서상 정확도가 가장 높아서 질문은 영어로 쓴다.

`state`에는 익명화한 특징과 정의만 넣는다. 종목명·날짜·시각·절대 가격은 넣지 않는다. 값은 소수 셋째 자리에서 반올림한다.

| 특징 | 정의 |
|---|---|
| `ret_1`, `ret_5`, `ret_15`, `ret_60` | 해당 봉 수 로그수익률(%) |
| `breakout_margin_atr` | (종가 − 채널 상단) / ATR14 |
| `atr_regime` | ATR14 / ATR240 |
| `volume_z` | 신호 봉 거래량의 직전 60봉 대비 z-score |
| `taker_buy_ratio` | 신호 봉 taker 매수량 / 거래량 |
| `range_pos_240` | 직전 240봉 고저 범위 안의 종가 위치(0~1) |
| `trend_slope_atr` | (EMA60 − 15봉 전 EMA60) / ATR14 |
| `bars_since_prev_signal` | 직전 진입 후보 이후 경과 봉 수(최대 240) |

질문:

```json
{
  "type": "noul",
  "instructions": "A long breakout entry signal just fired on a 1-minute chart of a liquid market. Using only the anonymized features in the state, will this trade more likely fail than succeed?",
  "criteria": {
    "true": "Price is more likely to close 2 ATR below entry, or reach the 120-minute limit without closing 3 ATR above entry, before it closes 3 ATR above entry.",
    "false": "Price is more likely to close 3 ATR above entry before closing 2 ATR below entry, within 120 minutes."
  }
}
```

- 응답 `answers.fail.noul`을 `p_fail`로 쓴다. 이 값을 수익 확률로 표시하지 않는다.
- 캐시 키는 `sha256(정규화 state JSON + 질문 JSON + 모델 ID)`다. 응답, 지연, 실제 모델, 입력 토큰, HTTP 상태, 오류 종류를 함께 저장한다.
- 호출은 한 번에 하나씩 순차로 보낸다. 동시 호출로 지연이 부풀지 않게 하기 위해서다. 타임아웃은 10초, 재시도는 없다.
- 호출 전에 누적 입력 토큰으로 비용을 계산하고, $5에 도달하면 중단한다.
- API 키는 `TYPESAFE_API_KEY` 환경 변수 또는 권한 0600의 `~/.config/typesafe/api_key`에서 메모리로만 읽는다. 로그·원장·Git에 남기지 않는다.

## 5. 비교 갈래

| # | 갈래 | 차단 규칙 | 맞추는 것 |
|---|---|---|---|
| ① | 규칙 단독 | 차단 없음 | — |
| ② | 결정론 필터 | `volume_z < q`이면 차단 | q는 개발 구간에서 ⑥의 차단율에 맞춤 |
| ③ | 무작위 차단 | 후보마다 확률 p로 차단, 시드 1,000개 | p = 같은 구간 ⑥의 실제 차단율 |
| ④ | 로지스틱 회귀 | 같은 특징으로 손실 확률 예측, 임계값 이상이면 차단 | 개발 구간 후보 거래로 학습하고, 임계값은 개발 구간 ⑥ 차단율에 맞춤 |
| ⑤ | JEV, 지연 0 | `p_fail ≥ τ` | ⑥과 같은 호출 결과, 결정 시각 = 봉 마감 |
| ⑥ | JEV, 실측 지연 | `p_fail ≥ τ` | — |

참고선으로 현금과 매수보유를 함께 표시한다. 해석은 다음과 같다.

- 매수보유 대비: 시장 효과
- ③ 대비: 거래 감소 효과
- ②·④ 대비: 판단 품질
- ⑤ 대비 ⑥: 지연 비용

### 임계값 τ

개발 구간에서 {0.3, 0.4, 0.5, 0.6, 0.7} 중 비용 차감 수익률이 가장 높은 값을 고른다. 단 차단율은 60% 이하여야 한다. 검증 구간에서 확인만 하고 다시 고르지 않는다.

## 6. 평가

- **지표:** 비용 차감 수익률, 최대 낙폭, 거래 수, 거래당 손익, 노출 시간 비율, stale 비율, 실패율, 호출 수, 입력 토큰, API 비용, 수수료·슬리피지 합계.
- **판정 품질:** 모든 후보의 가상 거래(지연 0, 규칙 청산)를 손실 여부로 라벨링한다. `p_fail`의 AUC와 Brier 점수, 10분위 보정표를 낸다.
- **통계:** 갈래 간 차이는 UTC 일 단위 블록 부트스트랩(2,000회) 95% 신뢰구간으로 보고한다. ③은 1,000개 시드 분포 안에서 ⑥의 백분위로 보고한다.
- **국면:** UTC 날짜마다 그 날 시작 전 30일 수익률이 +5% 초과면 상승, −5% 미만이면 하락, 그 사이면 횡보로 라벨링하고, 거래는 진입일 라벨을 따른다. 기준은 사전등록 파일에 고정한다.
- **오염 점검:** 공개 이후 구간(2026-09-11~)을 따로 보고한다. 홀드아웃 후보 중 200건은 종목명·날짜·절대 가격을 넣은 원본 입력으로 한 번 더 호출해 익명 입력 결과와의 일치율을 본다.
- **사전등록:** 구간, N 후보, 청산 규칙, 비용, stale 상한, 특징 정의, 질문 해시, τ 후보, 맞춤 규칙, 국면 기준, Stage 0 기준을 `lab/jev_gate/prereg.json`에 커밋한 뒤 Stage 0을 시작한다. 홀드아웃을 열기 전에 선택한 N·τ·q·로지스틱 계수를 `lab/jev_gate/prereg_holdout.json`으로 커밋한다. 홀드아웃은 한 번만 연다.
- **시도 원장:** 설정 해시·구간·결과 요약을 `lab/attempts.jsonl`에 한 줄씩 추가하고 Git으로 추적한다. 리포트에 총 시도 수를 적는다.

## 7. Stage 0 — 실현 가능성 확인

개발 구간 1분봉만 쓴다. 수익성은 판단하지 않는다.

1. 규칙 단독으로 N별 후보 수와 비용 차감 성과(지연 0, 1분봉 종가 근사)를 낸다.
2. 후보 300건을 무작위로 뽑아 순차 호출한다. 서로 다른 시간대에 세 번 나눠 실행하고 회차별 시각을 기록한다.
3. 그중 50건을 5회씩 반복 호출해 `p_fail`의 0.5 기준 판정 일치율과 표준편차를 낸다.
4. 지연 p50/p95/p99, 실패율, 스키마 유효율, 호출당 입력 토큰, 실제 모델 ID를 낸다.
5. 전체 백테스트의 호출 수·비용·소요 시간을 추정한다.

통과 기준(사전등록):

| 기준 | 값 |
|---|---|
| 지연 p99 | 5초 이하 |
| 실패·타임아웃율 | 2% 이하 |
| 스키마 유효율 | 99% 이상 |
| 반복 판정 일치율 | 90% 이상 |
| 개발 구간 후보 수(선택한 N) | 300건 이상 |
| 전체 예상 비용 | $5 이하 |

미달 시 대응:

- 지연 꼬리가 길면 5분봉으로 바꾸거나, 지연 비용을 주결과로 삼는다.
- 반복 일치율이 낮으면 3회 다수결로 바꾸고 재현성 한계를 명시한다.
- 후보가 부족하면 개발 구간 안에서 N을 바꾼다. 홀드아웃은 건드리지 않는다.
- 규칙 단독이 비용 전에도 손실이면 게이트 효과를 "손실 전략 차단"으로만 해석한다고 명시하거나 규칙을 다시 고른다. 바꿀 경우 시도 원장에 남긴다.

## 8. 코드 구조

새 의존성 없이 `requirements.txt`에 있는 pandas·numpy·scikit-learn·httpx만 쓴다. 독립 패키지로 두고 MVP에서는 FastAPI와 연결하지 않는다.

| 모듈 | 책임 | 입력 → 출력 |

## 11. 테스트

외부 API를 호출하지 않는다. JEV는 가짜 게이트로 대체한다.

- 시간 단위: 밀리초·마이크로초 입력이 같은 정수로 정규화된다.
- 미래 정보 누수: 특징·후보 판정이 이후 봉을 바꿔도 앞 행에서 변하지 않는다.
- 체결: 결정 시각과 같은 시각의 체결은 포함하고, 그 이전 체결은 쓰지 않는다. 지연 5초 초과는 stale이다.
- 재생: 포지션은 항상 하나 이하이고, 보유 중 후보는 무시되며, 비용 계산이 손으로 계산한 값과 일치한다.
- 갈래: 무작위 차단의 평균 차단율이 목표 p에 수렴하고, ⑤와 ⑥이 같은 게이트 결과를 쓴다.
- 게이트: 캐시 키가 입력 순서와 무관하게 같고, 실패 응답은 차단이며, 예산 상한에서 호출이 멈춘다.

## 12. 포트폴리오 주장

근거가 생긴 뒤에만 쓴다.

- 미래 정보를 쓰지 않는 이벤트 재생과 지연 반영 체결 모형(테스트 근거 첨부)
- 측정 환경을 밝힌 JEV 지연 p50/p95/p99와 실패율
- 대조군 대비 JEV 게이트 효과 추정치와 신뢰구간(방향 무관)
- 재현 가능한 실험 원장(모델 ID, 질문 해시, 데이터 체크섬, 시도 수)

쓰지 않는다: HFT·틱 단위 실행 능력, 예측 알파, 수익 보장, 실거래 적합성, 처리량 한도(40 req/s)를 지연 성능처럼 제시, JEV가 판단 이유를 설명한다는 주장, 단일 실행 결과의 일반화.

## 13. 범위 밖 (후속)

- Stage 2: 거래소 공지 같은 텍스트 특징을 넣은 갈래(JEV가 자유 서식 텍스트에서 효과를 낸 기록 기반)
- JEV가 매 봉 BUY/SELL/HOLD를 직접 고르는 방식
- 틱·호가 재생, 지정가·대기열 모형

- Stage 3: 앱 화면 연동, 실시간 모의 기록

## 14. 남은 위험

- JEV 학습 기준일이 공개 자료에 없다. `jev-latest` 별칭 공개일은 2026-09-10이다(`GET /v1/models`). 홀드아웃은 그 이전이라 학습 오염을 배제할 수 없고, 익명화와 공개 이후 구간 보고로만 완화한다.
- 지연은 서울 가정 네트워크에서 잰 값이다. 기존 기록은 단건 470~860ms, 평가 p50 231ms였다.
- 문서상 rate limit은 예고 없이 바뀔 수 있다.
