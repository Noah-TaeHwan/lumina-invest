## 1. 목적

강사님 보일러플레이트의 부품을 조립해 **AI 답변의 문장마다 근거를 판정하고 출처를 붙이는 리서치 어시스턴트**를 만든다. 쓰는 부품은 DART 수집, Qdrant, Ollama LLM 클라이언트, 종목 시드다.

이 spec은 그 핵심인 **판정 엔진**과 그 **평가**만 다룬다. 채팅 화면 연결(배지, 저장, 장애 처리, 사용자 입력의 외부 전송 고지)은 평가 결과를 본 뒤 별도 spec(모듈 A-2)으로 만든다. 연결에는 동기·비동기 저장 경로 통합, 기업 식별, 응답 스키마가 걸려 있어 판정력 측정과 섞으면 둘 다 흐려진다.

포트폴리오가 보여주는 것:

1. 보일러플레이트를 조립해 README 목표 "자료 확인 → AI 설명 → 판단 기록"의 첫 연결부(근거 판정)를 만들었다.
2. JEV가 강한 의미 판단과 약한 숫자 비교를 나눠 설계했다.
3. 한국어 공시 문장에서 판정력을 사전등록·홀드아웃·기준선 비교로 측정했다. 결과가 부정이어도 같은 형식으로 공개한다.

| 모듈 | 내용 | 상태 |
|---|---|---|
| A-1 | 근거 판정 엔진과 평가 | 이 spec |
| A-2 | 채팅 연결(화면, 저장, 장애 처리) | A-1 결과 뒤 별도 spec |
| B | 뉴스·헤드라인 판단 피드 | 별도 spec |
| C | 투자 판단 일지 | 별도 spec |

### 가설

| ID | 가설 | 판정 근거 |
|---|---|---|
| H-ko | JEV는 한국어 공시 문단이 주장을 지지하는지 무작위보다 확실히 잘 판정한다 | Stage 0, 개발-확인 세트 AUC |
| H-judge (주결과) | 홀드아웃 자연 주장에서 SYS(JEV + 숫자 존재 확인)의 지지 점수가 개발 세트에서 고른 최고 기준선보다 지지 주장을 잘 가려낸다 | AUC 차이와 2단 군집 부트스트랩 95% 구간 |
| H-latency | 주장 하나의 판정 요청이 대화형 사용에 맞는 시간 안에 끝난다 | 요청 지연 p50/p95/p99 |

통계 판정(우월성 확인, 열등성 확인, 판단 불가)과 실용적 동등 여부를 따로 보고한다(6절).

### 사전 근거

- 공식 citation check 쿡북은 영어(jev-1.12)에서 지지·반박·무관 3분류를 시연했다.
- 노아의 한국어 실측은 닫힌 선택지 과제(명령 라우팅, 공지 분류)에서 높았다.
- 한국어 문단–주장 지지 판정은 아직 측정된 적이 없다. TypeSafe 문서도 한국어는 처리하지만 영어와 동등하지 않다고 적는다.
- 그래서 H-ko를 Stage 0의 첫 관문으로 둔다.

### 판정 규칙 (SYS)

판정기는 문단 j마다 `s_j = p(supports)`와 `c_j = p(contradicts)`를 받는다.

숫자 존재 확인을 통과한 문단 집합을 V, `S_V = max_{j∈V} s_j`(V가 비면 0)로 둔다.

1. `max c_j ≥ τ_c`이고 `max c_j > S_V`이면 **반박**이다. 숫자 확인에 실패한 문단의 지지 점수는 반박을 막지 못한다.
2. 반박이 아니고 `S_V ≥ τ_s`이면, V에서 `s_j`가 가장 큰 문단을 출처로 붙이고 **지지됨**으로 둔다.
3. 그 밖에는 **근거 없음**이다.
4. **SYS 점수**는 규칙 1이 발동하면 0, 아니면 `S_V`다. AUC는 이 점수로 계산한다.
5. 임계값은 정해진 순서로 고른다. 후보는 0.05~0.95, 0.05 간격이다.
   - 먼저 τ_c: 규칙 1은 τ_s와 무관하므로, 조정 세트에서 반박 대 나머지 F1이 최대인 값을 고른다.
   - 다음 τ_s(τ_c 고정): 지지됨 정밀도 0.90 이상인 값 중 가장 작은 값을 고른다. 없으면 지지됨 F1 최대인 값을 고른다.
   - 동률이면 큰 값을 고른다.
6. 여러 문단을 합쳐야 지지되는 주장은 근거 없음으로 처리하고, 이 한계를 리포트에 적는다.
7. 첫 요청과 재시도 1회가 모두 실패하면 그 주장의 JEV·SYS 점수는 0이다. 타임아웃은 10초다. 응답 키가 보낸 후보와 다르거나, 선택지 확률이 하나라도 빠지거나 유한한 [0, 1] 값이 아니거나, 합이 0.99~1.01을 벗어나면 실패로 본다. 실패 건수는 따로 보고한다.

Stage 0에는 숫자 존재 확인이 없으므로 V는 모든 문단이다.

## 4. 평가 데이터

### 질문

- 기업마다 질문 6개를 만든다. 범주는 사업 개요, 주요 제품·서비스, 매출 구성·수치, 원재료·생산설비, 위험·파생, 연구개발·주요계약이고 범주마다 1개다.
- 질문 수는 `split.json`의 기업 수 × 6이다(홀드아웃 최대 120개).
- 질문 작성자는 해당 기업 원문 절을 읽는 AI 작성자(Claude 서브에이전트)다. 질문에 답을 넣지 않는다.

### 주장

질문마다 k=8 문단을 검색한다.

| 출처 | 만드는 법 | 쓰임 |
|---|---|---|
| 자연 | `generate_answer`가 쓴 답변의 앞 5문장까지 | 주결과 |
| 통제 | 질문마다 2개. 문단 내용을 **의역**한 참 문장 1개와 변형 1개(숫자 변경, 기간 바꾸기, 주체 교체, 부정, 같은 분할 안 다른 기업 사실 중 순환 배정). 변형에 넣는 숫자·연도·회사명은 그 질문의 문단 8개 어디에도 없는 값으로 고르고 코드로 확인한다 | 진단, 라벨 타당도 점검 |

- 자연 주장은 클래스 균형을 강요하지 않는다.
- 생성 실패, 비문, 제외 사례를 모두 기록한다.

### 라벨

- **정의**
  - **지지됨**: 문장의 모든 사실 단위를 보여 준 문단 하나가 지지할 때다.
  - **반박**: 어떤 문단이 같은 주체·기간·지표에 대해 다른 사실을 말할 때다. 한 문단은 지지하고 다른 문단은 반박하면(상충) 반박으로 둔다.
  - **근거 없음**: 나머지다.
  - **비주장**: 사과, 질문, 면책, 의견, 절차 문장이다. 비주장은 평가에서 뺀다.
  - 기준은 보여 준 문단 8개다. 세상 지식은 쓰지 않는다.
- **라벨러**: 서로 다른 계열의 AI 2개(Claude Opus 서브에이전트, Codex)다.
  - 각자 독립적으로 라벨, 근거 문단 번호, 한 줄 이유를 낸다.
  - 주장의 출처(자연/통제), 변형 유형, 판정기 결과를 보지 않는다.
- **불일치 처리**
  - 두 라벨러가 상대의 라벨과 이유를 보고 한 번 다시 판정한다(조정 라운드).
  - 그래도 다르면 주결과에서 빼고, 민감도 분석에서 양쪽 라벨로 각각 계산해 보고한다. 제외율과 제외 사례의 클래스·군집 분포도 함께 보고한다.
  - 같은 계열 판정자를 세우지 않는다. 한 계열 쪽으로 기울지 않게 하기 위해서다.
- **타당도 점검**
  - 통제 주장의 기대 라벨은 이진으로만 쓴다. 라벨러 어느 한쪽이라도 기대 라벨과 다르게 붙인 통제 주장은, 작성자가 문단 8개 전체와 대조해 기대 라벨을 확정하거나 진단 세트에서 뺀다(사유 기록). 의역은 지지됨, 변형은 지지 안 됨이다. 변형 값이 문단 8개에 없음을 코드로 확인했으므로 변형이 지지될 경로는 막혀 있다. 의역이 뜻을 바꿨을 위험은 남으므로, 라벨러가 지지 안 됨을 준 의역은 작성자가 원문과 대조해 기대 라벨을 확정한다.
  - κ는 조정 라운드 **전** 독립 라벨로 계산한다.
  - 숫자가 든 주장 중 무작위 50개는 작성자가 원문 XML과 직접 대조한다.
- **이름 붙이기**: 정답 라벨은 사람이 아니라 AI가 만들었다. 그래서 결과를 "**AI 참조 라벨과의 일치 성능**"이라고 부르고 리포트 첫 화면에 적는다.
- **노아 감사(선택)**: 사람 확인은 노아만 할 수 있어 선택 항목으로 남긴다. 홀드아웃 주장 50개를 노아가 감사하면 AI 라벨 오류율을 보고한다. 하지 않으면 그렇다고 적는다.
- JEV는 라벨 과정에 쓰지 않는다.

## 5. 기준선

어느 기준선도 JEV 출력으로 학습하지 않는다.

| ID | 기준선 | 점수 |
|---|---|---|
| B-lex | 숫자 존재 확인 + 어휘 겹침(주장 토큰 중 문단에 나오는 비율)의 문단별 최댓값. 숫자 확인을 통과하지 못한 문단은 0 | 겹침 비율 |
| B-emb | 임베딩 코사인 최댓값(`nomic-embed-text`) | 유사도 |
| B-nli | 다국어 NLI 교차 인코더 `MoritzLaurer/mDeBERTa-v3-base-xnli-multilingual-nli-2mil7`의 문단별 entailment 확률 최댓값. 평가 하네스 전용 의존성이고 앱 의존성에는 넣지 않는다 | 확률 |
| B-llm | 생성기와 같은 로컬 LLM에게 같은 질문을 하고 0~100 점수를 받는다(현재 앱의 방식) | 점수 |
| JEV | 문단별 `p(supports)` 최댓값 | 확률 |
| SYS | 3절 규칙 4 | 점수 |

**최고 기준선 B\***은 조정 세트 자연 주장 AUC가 가장 높은 기준선으로 정하고 동결한다. 부트스트랩 반복마다 다시 고르지 않는다.

## 6. 지표와 판정

- **주결과:** 홀드아웃 자연 주장에서 `Δ = AUC(SYS) − AUC(B*)`.
  - 95% 구간은 **2단 군집 부트스트랩**으로 낸다. 1단은 군집, 2단은 군집 안 질문이고 2,000회, 시드 20261002다.
  - 모든 판정기를 같은 재표집 표본에서 비교한다.
- **판정:**
  - **통계 판정**(셋 중 하나): 하한 > 0이면 **우월성 확인**, 상한 < 0이면 **열등성 확인**, 그 밖에는 **판단 불가**다.
  - **실용적 동등**(별도 표시): 구간 전체가 [−0.05, +0.05] 안에 있으면 "실용적으로 동등"을 함께 적는다. 예를 들어 구간 [0.01, 0.03]은 "우월성 확인, 실용적으로 동등"이다.
- **검정력:** Stage 0이 끝난 뒤 개발 자료로 MDE(80%, 양측 0.05)를 추정해 사전등록 파일에 적는다. 방법은 다음과 같다. 개발 자연 주장에 JEV와 기준선 점수를 붙인 표에서, 홀드아웃과 같은 군집 수·군집 크기로 2단 군집 부트스트랩을 해 Δ의 표준오차 SE를 구하고, MDE = 2.8 × SE로 둔다. MDE가 0.10을 넘으면 홀드아웃 라벨을 만들기 전에 기업당 질문 수를 늘린다(최대 10개). 그래도 0.10을 넘으면 주결과를 **탐색적 평가**로 미리 낮춰 사전등록 파일에 적고, 우월성·열등성 주장을 하지 않는다.
- **표본 하한:** 홀드아웃 자연 주장의 지지됨과 지지 안 됨이 각각 60개 미만이면 주결과를 기술 통계로만 보고한다.
- **운영점:** 홀드아웃에서 τ_s로 낸 지지됨 정밀도·재현율·커버리지와 반박 오탐률을 본다.
- **보조 지표:**
  - JEV 단독 대 B*
  - 숫자가 없는 주장만의 AUC
  - 3분류 macro-F1
  - 통제 주장 변형 유형별 정확도
  - 군집별 Δ 부호 일치 수
  - 라벨 조정 불일치 사례의 민감도
- **지연·안정성:**
  - 요청 지연 p50/p95/p99
  - 실패율(분모는 재시도 전 첫 요청 수)
  - 반복 일치율. 캐시를 끄고 같은 요청을 3회 보낸다.
- **사용량:** 호출 수와 입력 토큰 수만 공개한다(9절).

## 7. 단계와 관문

### 사전등록 (Stage 0 전)

`lab/evidence/prereg.json` v1을 JEV 호출 전에 커밋한다. 담는 것은 다음과 같다.

- 분할 결과 해시
- 라벨 정의와 프롬프트
- 판정 질문 문구 초안

- 지표와 판정 규칙
- 중지 조건
- 예산 하드 상한(입력 토큰 20,000,000)

이후 바꾸는 모든 것은 `lab/evidence/attempts.jsonl` 원장에 이유와 함께 남긴다.

### Stage 0 — 실현 가능성 (조정·확인 세트만)

**범위:**

- 수집과 문단 분해(40개사)
- 검색
- 답변 생성과 동결(개발만)
- 주장 분해
- 라벨 수합
- JEV 클라이언트와 판정기(JEV 부분)

숫자 존재 확인과 SYS 규칙은 Stage 1에서 붙인다. 한국어 판정 관문을 고정 쌍이 아니라 이 파이프라인 뒤에 두는 이유는, 주결과의 대상이 생성기가 실제로 만든 자연 주장이기 때문이다. 고정 쌍으로 통과해도 자연 주장 분포에서 다시 재야 한다. 홀드아웃 기업은 문단 분해까지만 하고 질문·답변·주장·라벨을 만들지 않는다.

| 기준 | 통과 조건 |
|---|---|
| 코퍼스 | 40개사 중 38개사 이상 지정 절 분해. 실패한 무작위 기업은 같은 추첨 순서의 다음 후보로 바꾸고, 교차 언급 군집과 분할을 다시 계산해 `split.json`을 다시 커밋한다(JEV 호출 전에만 허용, 원장 기록) |
| 라벨 품질 | 개발 자연 주장의 이진 κ ≥ 0.6(군집 부트스트랩 구간 함께 보고). 통제 주장 정답 일치율 ≥ 0.85 |
| H-ko | 확인 세트 자연 주장에서 JEV AUC ≥ 0.70, 군집 부트스트랩 95% 하한 > 0.5. 문구 조정에는 조정 세트만 쓴다 |
| 질문 묶기 | 주장 50개를 묶음 요청과 문단별 단건 요청으로 보냈을 때 문단별 최댓값 라벨 일치율 ≥ 0.90 |
| 지연·실패 | 첫 요청 300회 이상, 1시간 이상 떨어진 두 세션 이상에 나눠 보낸다. p95 ≤ 1.5초, 실패율 단측 95% 상한(Clopper–Pearson) ≤ 2%. 세션별 지연과 입력 토큰 분포를 함께 보고한다 |
| 반복 일관성 | 캐시를 끈 요청 50건 × 3회에서 최댓값 문단과 3분류 판정 일치율 ≥ 0.90 |

**판정:** 모두 통과하면 GO, 하나라도 미달이면 NO-GO다. NO-GO여도 결과를 공개한다. H-ko가 원인이면 모듈 B(닫힌 선택지 분류)로 옮긴다.

### Stage 1 — 판정력 평가

1. 조정 세트로 판정 질문 문구, τ_s, τ_c를 확정한다. 확인 세트로 확인한다.
2. B*를 정한다.
3. 검정력을 추정해 기록한다.
4. 생성 프롬프트, 라벨러 프롬프트·모델 식별자, 통제 주장 작성 규칙을 사전등록 파일에 커밋한다. 그다음 홀드아웃 질문·답변·주장·라벨을 만든다. 라벨은 JEV와 기준선을 실행하기 전에 끝낸다.
5. 동결 묶음을 `lab/evidence/prereg_holdout.json`에 담아 커밋한다. 묶음에 들어가는 해시는 다음과 같다.
   - 원문 해시, 문단, 검색 순위
   - 답변, 주장, 라벨
   - 생성기·임베딩 모델 digest, 생성 프롬프트, 판정 프롬프트, B-llm 프롬프트, B-nli 모델 리비전, 임계값, B*
   - 라벨러 프롬프트와 라벨러 모델 식별자(Claude·Codex 버전 문자열)
   - 기준선 코드 커밋
6. 동결 커밋 뒤 홀드아웃에서 모든 판정기를 한 번 실행한다. 다시 열지 않는다.

## 11. 공개 원칙과 한계

- 결과가 부정이어도 같은 형식으로 공개한다.
- 리포트 첫 화면에 적을 한계:
  - 정답이 AI 참조 라벨이다.
  - 한국 상장사 40개사, 사업보고서 2개 절만 다룬다.
  - 생성기가 소형 로컬 모델이다.
  - 판정은 보여 준 문단 8개 기준이고 세상 지식의 진위가 아니다. 화면 문구는 "검색된 문단에서 확인되지 않음"으로 쓴다.
  - 여러 문단을 합쳐야 하는 주장은 처리하지 않는다.
  - 계열 관계는 본문 교차 언급으로만 확인한다. 언급 없이 지분으로만 얽힌 관계는 놓칠 수 있다.
  - 공개 결정은 현행 MCA 문언만을 근거로 한다. 노아 계정의 Order에 별도 조건이 있는지는 확인하지 못했다.
  - 2025 사업보고서가 JEV 학습 시점보다 앞서 공개됐을 수 있다. 그래서 세상 지식이 판정에 섞일 수 있다.
- 작성자는 DART 접근 시험 중 삼성전자(시드) 2026년 반기보고서 "사업의 개요" 앞부분 약 600자를 보았다. 평가 코퍼스는 2025 사업보고서이고, 질문·주장 작성은 별도 서브에이전트가 맡는다.
- 정보 정리 도구다. 매수·매도 권유나 수익 예측을 하지 않는다.
