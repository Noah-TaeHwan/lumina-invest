# 근거 판정 A-2 평가 — 해석과 한계

- 날짜: 2026-10-04
- 작성: AI(Claude Code)가 작성한 해석이다. 수치는 자동 리포트 [`evidence-a2-report.md`](evidence-a2-report.md)와 원자료 [`a2-check.json`](../../lab/evidence/results/a2-check.json), 보조 분석 [`a2-check-supplementary.json`](../../lab/evidence/results/a2-check-supplementary.json)에서 왔다.
- 정답은 AI 참조 라벨(Claude Opus·Codex 독립 라벨 → 조정)이다. 사람 감사는 하지 않았다. 판정에는 외부 문장 판정 모델을 썼다.

## 결론

**판정 모델을 붙인 판정기(SYS)는 서비스 생성기(llama3.1:8b) 답변에서 ✅ 정밀도 약 0.90을 냈다. 다만 사전등록한 관문 기준으로는 정밀도 목표가 "확인됨"이 아니다.** 단순 어휘 겹침보다 낫다는 증거도 없었다.

| 질문 | 결과 |
|---|---|
| ✅ 정밀도 0.90 이상인가(H-prec) | 정밀도 0.903(95% 0.829~0.961). 점추정과 구간 하한은 관문 값을 넘었지만, ✅ 예측이 144건(사전등록 하한 150건 미만)이라 **기술 통계로만** 보고한다 → 관문 실패 |
| 어휘 겹침이 낮은 주장을 판정 모델 없이 ❔로 둬도 되나(H-low) | 조정 세트에서 쓸 구간이 없었다(어휘 겹침 최하단에서도 지지 주장이 12% 이상). 미시험 |
| 어휘 겹침이 아주 높은 주장을 판정 모델 없이 ✅로 둬도 되나(H-high) | **통과.** 확인 세트 상단 구간 50건이 모두 지지(정밀도 1.0) |
| 계층형 판정이 SYS와 동등하면서 판정 모델 호출을 30% 이상 줄이나(H-tier) | AUC 차이는 동등 범위(+0.014, 95% 0.001~0.044)였지만 호출 감소가 16.9%라 **실패** |
| SYS가 어휘 겹침보다 나은가 | AUC 차이 −0.012(95% −0.061~0.034). 우열을 가릴 수 없고, 하한 −0.061이 동등성 마진 −0.05 밖이라 실용적 동등도 아니다 |

## 무엇이 확인됐고 무엇이 안 됐나

- **Stage 1 리포트가 시사한 방향("서비스 생성기는 의역하므로 판정 모델의 이점이 커질 수 있다", 사전등록 결론은 아니었음)은 주장 단위 AUC로 확인되지 않았다.** 8B 답변에서도 SYS와 어휘 겹침의 차이를 가리지 못했다.
- **판정 모델이 강한 곳은 그대로였다.** 통제 주장에서 숫자·기간·부정·다른 기업 변형은 모두 1.00, 의역은 0.93이었다.
- **약점도 그대로였다.** 주체 교체 정확도 0.57(A-1 0.45). 회사·부문 이름만 바꾼 문장은 여전히 많이 ✅로 넘어간다.
- 8B 생성 지연(첫 호출 제외)은 확인 세트 p50 약 15초·p95 약 26초, 조정 세트 p50 약 15초·p95 약 23초였다. p95 × 2 타임아웃 재설정값은 확인 세트 기준 약 52초(조정 세트 약 47초)다.

## 사전등록 규칙의 역전(중요)

- 조정 세트는 τ_s 0.90을 골랐다. 확인 세트에서 0.90의 정밀도는 0.903이었지만 ✅ 예측이 150건에 6건 모자라 H-prec가 기술 통계로 떨어졌다.
- 사전등록 반영 규칙상 H-prec 실패면 τ_s를 **0.85**로 둔다. 이 폴백은 잠정값 0.70보다 높은, 보수적인 값으로 의도한 것으로 읽힌다(spec 6.4의 "보수적으로 둔 시험 운영" 문구). 이번처럼 조정값(0.90)보다 **낮아지는** 경우는 규칙이 다루지 않았다.
- 정책 `a2-v1`은 사전등록대로 τ_s 0.85다. 결과를 보고 값을 다시 고르지 않는다.
- 저장된 확률로 계산한 0.85의 성능(기술 통계, 추가 호출 없음): ✅ 예측 151건, 정밀도 0.901, 재현율 0.932, 커버리지 0.588. 0.90(정밀도 0.903, 재현율 0.890)과 정밀도는 거의 같고 재현율이 조금 높다.
- 이 폴백 규칙의 결함은 다음 사전등록에서 고친다. `max(조정값, 폴백)`은 이번처럼 예측 수가 모자란 경우만 고치고, 정밀도가 모자라 실패한 경우에는 별도 규칙이 필요하다.
- **P6은 사전등록대로 τ_s 0.85를 적용한다.** 확인 세트를 본 뒤 0.90 등 다른 값을 고르는 것은 사후 재선택이므로, 다른 값을 쓰려면 새 데이터로 새 사전등록을 해야 한다.
- 사전등록의 툴팁 문구 "확신도 기준을 보수적으로 둔 시험 운영"은 이번 경우(0.85 < 조정값 0.90) 사실과 맞지 않는다. P6에서는 "정밀도 목표를 확인하지 못한 시험 운영"처럼 사실에 맞는 문구를 쓴다(값은 바꾸지 않는다).

## 라벨 민감도

조정 뒤에도 두 라벨러가 갈린 자연 주장 12건(통제 4건 별도)을 한쪽 라벨로 넣어 다시 계산했다(저장된 점수 사용). 양쪽 모두 12건 중 2건은 2차 라벨이 non_claim이라 빠져 판정 대상이 257+10=267건이 된다.

| 라벨 처리 | 판정 대상 | τ_s 0.90 ✅ 정밀도 | SYS − 어휘 AUC(95%) |
|---|---|---|---|
| 주결과(갈린 주장 제외) | 257 | 0.903 | −0.012(−0.061~0.034) |
| 갈린 주장 = Opus 2차 라벨 | 267 | 0.886 | −0.002(−0.057~0.056) |
| 갈린 주장 = Codex 2차 라벨 | 267 | 0.885 | +0.005(−0.047~0.065) |

어느 쪽으로 넣어도 "어휘 겹침과 우열 불명"이라는 결론은 같다. ✅ 정밀도는 0.89 근처로 조금 내려간다.

## 한계

- 정답이 AI 참조 라벨이다. 1차 이진 κ는 조정 0.967, 확인 0.940이었지만 사람 감사는 하지 않았다.
- 확인 세트는 20개사·자연 주장 257건이다. ✅ 예측이 150건 미만이라 정밀도 관문을 기술 통계로만 보고했다.
- 판정은 검색 문단 8개 기준이고, 검색은 `nomic-embed-text`다. 검색이 놓친 근거는 ❔가 된다.
- 생성기·임베딩·판정 모델 버전은 사전등록에 고정했다(llama3.1:8b `46e0c10c039e`, nomic `0a109f422b47`, 판정 모델 버전 1.13.0). 하나라도 바뀌면 같은 절차로 다시 잰다(spec 6.5).
